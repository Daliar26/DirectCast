# DirectCast 0.3 — экран телефона на проектор по Wi‑Fi

Android-приложение: телефон (Передатчик) показывает свой экран и звук на проекторе (Приёмник) по локальной сети — через точку доступа телефона или общий Wi‑Fi. Интернет не нужен.

Целевые устройства: Redmi 12 (Передатчик) → проектор на Android 10 (Приёмник). Код проверен компиляцией и разбором манифеста; на реальных устройствах результат нужно подтвердить первым запуском.

## Установка

1. Скачайте APK: **https://github.com/Daliar26/DirectCast/releases/latest/download/DirectCast.apk**
   (или артефакт `DirectCast-debug` из вкладки Actions).
2. Установите **один и тот же APK на оба устройства**.
3. Если стоит старая версия 0.1 — удалите её один раз (подпись сборок изменилась). Дальше новые версии ставятся поверх без удаления.

## Как пользоваться

1. На телефоне включите точку доступа, на проекторе подключитесь к ней (или подключите оба устройства к одной Wi‑Fi сети).
2. Проектор: откройте DirectCast → «Приёмник». Экран покажет IP проектора и журнал.
3. Телефон: DirectCast → «Передатчик». Проектор находится сам (кнопка «Найти проектор»); если нет — введите IP с экрана проектора.
4. По желанию нажмите «Проверить связь» — проверяется и сеть, и совпадение версий.
5. «Начать трансляцию экрана» → разрешите захват экрана (и звук) → картинка пойдёт на проектор.
6. Совет: для видео поверните телефон горизонтально.

## Почему не соединялось в версии 0.1

| Причина | Что было | Что сделано |
|---|---|---|
| Нет foreground-сервиса `mediaProjection` | На Android 10+ без него `getMediaProjection()` падает с `SecurityException` — трансляция даже не стартовала | Сервис `CastService` с типом `mediaProjection`, уведомление с кнопкой «Остановить» |
| UDP без сборки кадров | Кадры > 60 КБ (а ключевые кадры всегда такие) выбрасывались, SPS/PPS мог потеряться → декодер не запускался, чёрный экран | TCP с длиной кадра; SPS/PPS отправляются первыми и берутся из ключевого кадра, если пришли иначе |
| Нет рукопожатия | «Трансляция запущена» писалось, даже если проектор недоступен | Проверка порта и версии до запроса захвата, понятные причины ошибок на экране телефона и проектора |
| Неверный IP на проекторе | Показывался первый попавшийся адрес любого интерфейса | Показываются адреса всех сетевых интерфейсов; автопоиск проектора (broadcast + опрос подсети /24) |
| Трафик уходил в мобильную сеть | Если у Wi‑Fi нет интернета, Android по умолчанию гонит соединения приложения через мобильную сеть, и 192.168.x.x недостижим | Сокеты привязываются к сети, в которой лежит адрес проектора |
| Манифест | Не было `CHANGE_WIFI_MULTICAST_STATE` (падала блокировка), приложение не отображалось в TV-лаунчере проектора | Права добавлены, добавлен `LEANBACK_LAUNCHER`, управление пультом |

## Устройство

- Телефон: `MediaProjection` → `VirtualDisplay` → кодер H.264 (`MediaCodec`, 720p/4 Мбит/с или 1080p/8 Мбит/с) → TCP, порт 5000. Звук приложений (Android 10+, `AudioPlaybackCapture`) — PCM 48 кГц стерео в том же потоке.
- Проектор: TCP-сервер (порт 5000), UDP-ответчик поиска (порт 5001), декодер H.264 прямо на `Surface`, `AudioTrack` для звука.
- Кадр: `тип (1 байт) | время (8) | размер (4) | данные`. Рукопожатие: `DCST | версия | ширина | высота`, ответ — 1 байт.

## Ограничения

- Звук берётся только у приложений, которые разрешают его захват (например, сервисы с защитой контента — нет).
- Звук и картинка не синхронизируются жёстко: возможна небольшая разница (доли секунды).
- Показ идёт без шифрования, только в локальной сети.
- Передача отдельных видеофайлов не реализована.

## Сборка

GitHub Actions (`.github/workflows/build.yml`) собирает APK при каждом пуше. Из ветки `main` APK дополнительно выкладывается в релиз `latest` по постоянной ссылке. Журнал последней сборки — в ветке `ci-logs`.

Подпись: используется постоянный debug-ключ из `signing/` (это не секретный ключ, он нужен только для того, чтобы обновления ставились поверх). Для публикации в магазине замените его своим.
